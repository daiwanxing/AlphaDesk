# A 股投研线索引擎（个人版）设计文档

**日期：** 2026-07-19  
**状态：** **已废弃** — 由 `2026-07-30-investment-research-platform-prd.md`（事件追踪 · 七姐妹 + FOMC）替代，本文档仅作历史参考  
**范围：** 个人自用；仅 A 股股票与境内 ETF；不做任何投资决策输出

---

## 1. 背景与目标

### 1.1 问题

在研究某一只 A 股或境内 ETF 时，相关信息分散在公告、新闻、同业动态、政策主题与 ETF 结构中。人工拼线索耗时，且容易只看到单边叙事。

### 1.2 产品目标

给定一只 **A 股股票或境内 ETF**，输出结构化、可追溯的 **投资研究线索**，帮助用户决定「下一步查什么」。  
**产品不替代用户做任何投资决策。**

### 1.3 成功标准（个人产品）

| 指标     | 说明                                                  |
| -------- | ----------------------------------------------------- |
| 可用速度 | 单标的在约 5 分钟内可获得 ≥3 条愿意继续点开的线索     |
| 可追溯   | 线索须带证据（来源标题、时间、链接或公告标识、摘录）  |
| 无来源率 | 无硬证据的卡片应被丢弃或标为极低置信，不得伪装成事实  |
| 反馈质量 | 用户「有用」占比可追踪；用于排序与模板改进            |
| 边界合规 | UI 与模型输出均不出现买卖建议、仓位、目标价、操作指令 |

**不作为成功标准：** 涨跌预测准确率、策略收益、荐股胜率。

## 2. 非目标（明确不做）

- 买卖点、仓位、目标价、评分式「操作建议」
- 实盘 / 模拟交易、跟单、信号订阅式荐股
- 策略回测驱动的「应如何交易」结论
- 全市场万能预测、收益排行榜
- 第一期不做：图谱可视化大屏、北交所细规则深化、复杂股权多层穿透、移动端优先

---

## 3. 用户与核心场景

### 3.1 用户

产品作者本人（单用户）。可不做复杂多租户；预留 `userId` 字段便于日后扩展。

### 3.2 核心场景

1. **单标的深挖：** 输入代码/名称 → 浏览分类型线索 → 点开证据 → 按「下一步 dig」继续研究
2. **ETF → 成分发散：** 查看跟踪指数与前十大成分事实 → 跳转成分股线索
3. **反馈闭环：** 对线索标记 有用 / 无关 / 过时
4. **（V0.2）自选增量：** 自选池每日拉取新公告/事件类线索

---

## 4. 产品边界与文案原则

| 要做                 | 不做                     |
| -------------------- | ------------------------ |
| 发散相关「研究线索」 | 给出买入/卖出/加减仓建议 |
| 解释为何相关 + 证据  | 承诺收益或暗示必涨必跌   |
| 强制风险与反方线     | 只展示利多叙事           |
| 待验证问题清单       | 替用户下结论             |

**统一用语：** 「投资线索 / 研究线索」。禁用：「推荐标的」「建议操作」「目标价」「强烈看多/看空（作为指令）」。

**页脚免责（全局）：**  
本工具仅提供研究线索整理，不构成投资建议。市场有风险，决策由用户自行做出并承担责任。

## 5. 线索模型

### 5.1 MVP 线索类型（6 类）

| 优先级 | type            | 说明                                                      |
| ------ | --------------- | --------------------------------------------------------- |
| P0     | `announcement`  | 事件与公告线（财报、合同、减持、回购、立案、问询等）      |
| P0     | `theme_policy`  | 主题与政策线                                              |
| P0     | `peer`          | 同业与可比线（帮助理解，非推荐列表）                      |
| P1     | `etf_structure` | ETF 结构线（跟踪指数、前十大、规模/份额事实、调样若可得） |
| P1     | `risk_counter`  | 风险与反方线（强制出现）                                  |
| P2     | `open_question` | 待验证问题（3–5 条研究检查项）                            |

### 5.2 线索卡片字段

```ts
interface Clue {
  _id?: string;
  jobId: string;
  entityId: string; // 主标的
  relatedEntityIds?: string[];
  type:
    "announcement" | "theme_policy" | "peer" | "etf_structure" | "risk_counter" | "open_question";
  title: string;
  whyRelated: string; // 1–3 句可解释原因
  evidence: {
    sourceTitle: string;
    url?: string;
    announcementId?: string;
    publishedAt?: string; // ISO 或 YYYY-MM-DD
    excerpt: string;
  }[];
  freshnessAt: string; // 线索所依据信息的时间
  confidence: "high" | "medium" | "low";
  nextDig: string[]; // 下一步研究动作
  tags?: string[];
  createdAt: string;
  modelMeta?: {
    model?: string;
    promptVersion?: string;
  };
  disclaimer: "research_clue_not_advice";
}
```

### 5.3 生成硬规则

1. **无检索命中不得编造**关联公司、政策或公告；应返回空列表或明确「暂无足够来源」。
2. **关系边优先结构化数据**（行业分类、ETF 成分等）；LLM 只做叙述、聚类与「下一步 dig」措辞。
3. **Schema 校验失败的卡片丢弃**（缺 type、title、或 evidence 为空且 type 非 `open_question` 时）。
4. `open_question` 可无外部 URL，但必须能追溯到本次 job 中已生成的其他线索或实体上下文。
5. 每个成功 job **至少尝试生成 1 条 `risk_counter`**；若无来源则写明「基于公开信息暂未检索到明确风险事件，建议自行核对：监管、竞争、估值与流动性」。
6. 输出禁止买卖/仓位/目标价类表述；后置过滤器二次拦截关键词。

## 6. 系统架构

### 6.1 总览

```text
┌─────────────────┐
│ Web 前端         │
│ (静态托管可选)   │
└────────┬────────┘
         │ HTTPS
         ▼
┌─────────────────────────────────────────────┐
│ 腾讯云 CloudBase                            │
│  · 云函数：API + 异步 Worker                │
│  · 云数据库（文档型）：实体/边/文档/线索/任务 │
│  · 云存储：原文/缓存（可选）                 │
│  · 定时触发器：自选增量（V0.2）              │
│  · 环境变量：LLM Key、数据源 Key            │
└────────┬────────────────────────────────────┘
         │ 出站 HTTPS
         ▼
   行情/公告等数据 API · LLM API
```

### 6.2 后端平台：CloudBase

| 能力                   | 用途                      |
| ---------------------- | ------------------------- |
| 云函数                 | HTTP API、线索生成 Worker |
| **云数据库（文档型）** | 主存储（见第 7 节）       |
| 云存储                 | 公告全文/附件缓存（可选） |
| 定时触发器             | 自选池增量任务（V0.2）    |
| 环境变量/配置          | 密钥，禁止下发前端        |

### 6.3 异步线索生成（必选模式）

同步「单次 HTTP 等待 LLM 全流程」仅可用于本地调试；**产品路径必须异步**：

```text
客户端 POST /api/clue-jobs { code | name }
  → API 云函数：解析实体、创建 job(status=pending)、返回 { jobId }
  → 触发 Worker（二次调用云函数 / 队列 / 定时捞取 pending）
  → Worker：retrieve → generate → validate → 写入 clues，job=done|failed
客户端 GET /api/clue-jobs/:jobId 或按 entityId 拉 clues
```

**原因：** 检索 + LLM 常超过云函数舒适同步时长；异步可重试、可记账、可避免网关超时。

### 6.4 逻辑分层

1. **输入层：** 代码/名称搜索
2. **实体层：** Stock / ETF / Industry / Theme / Event
3. **图谱层：** 仅存可核对的边（见 `edges`）
4. **检索层：** 公告、新闻/政策、基础元数据（事实，非预测）
5. **生成层：** LLM 仅基于检索片段与实体上下文输出 JSON 线索
6. **呈现层：** 分类型线索流、详情、反馈

## 7. 数据设计（CloudBase 云数据库 · 文档型）

主数据库采用 **CloudBase 云数据库（文档型 NoSQL）**。  
图谱不引入独立图数据库：用 **`edges` 集合** 表达关系，个人规模下按 `fromId` / `toId` / `type` 查询即可。

### 7.1 集合一览

| 集合        | 用途                                    |
| ----------- | --------------------------------------- |
| `entities`  | 股票、ETF、行业、主题等实体             |
| `edges`     | 有向/无向关系边（成分、同业、属主题等） |
| `documents` | 公告/新闻等证据文档（检索语料）         |
| `clue_jobs` | 异步生成任务                            |
| `clues`     | 生成后的线索卡片                        |
| `feedback`  | 用户对线索的反馈                        |
| `watchlist` | 自选（V0.2）                            |

### 7.2 集合字段草案

#### `entities`

```ts
{
  _id: string,
  kind: "stock" | "etf" | "industry" | "theme",
  code?: string,              // 如 300750.SZ / 510300.SH（统一规范在实现时定一种）
  name: string,
  market?: "SH" | "SZ" | "BJ",
  industryCode?: string,
  industryName?: string,
  // ETF
  trackIndexName?: string,
  trackIndexCode?: string,
  meta?: Record<string, unknown>,
  updatedAt: string
}
```

#### `edges`

```ts
{
  _id: string,
  fromId: string,
  toId: string,
  type:
    | "peer_same_industry"
    | "etf_holds"            // ETF → 成分股
    | "in_theme"
    | "related_announcement", // 可选：实体 → document
  source: string,            // 数据来源说明，如 "sw_industry" | "etf_holding_file"
  weight?: number,
  asOf?: string,             // 关系快照日期（成分尤其重要）
  createdAt: string
}
```

**查询模式示例：**

- 某股票同业：`fromId == entityId && type == peer_same_industry`（或对称存两条/查询 or）
- ETF 成分：`fromId == etfId && type == etf_holds`
- 主题：`fromId == entityId && type == in_theme`

#### `documents`

```ts
{
  _id: string,
  entityIds: string[],
  docType: "announcement" | "news" | "policy" | "other",
  title: string,
  url?: string,
  publishedAt?: string,
  excerpt?: string,
  storagePath?: string,      // 云存储路径（可选）
  rawHash?: string,          // 去重
  createdAt: string
}
```

#### `clue_jobs`

```ts
{
  _id: string,
  entityId: string,
  status: "pending" | "running" | "done" | "failed",
  errorMessage?: string,
  requestedAt: string,
  startedAt?: string,
  finishedAt?: string,
  params?: { forceRefresh?: boolean }
}
```

#### `clues`

见 §5.2；另加可索引字段：`entityId`、`type`、`createdAt`、`jobId`。

#### `feedback`

```ts
{
  _id: string,
  clueId: string,
  entityId: string,
  label: "useful" | "irrelevant" | "stale",
  createdAt: string
}
```

#### `watchlist`（V0.2）

```ts
{
  _id: string,
  entityId: string,
  code: string,
  createdAt: string
}
```

### 7.3 索引建议

| 集合        | 索引思路                                           |
| ----------- | -------------------------------------------------- |
| `entities`  | `code`；`name`（若支持）；`kind + code`            |
| `edges`     | `fromId + type`；`toId + type`                     |
| `documents` | `entityIds`（数组含）；`publishedAt`；`rawHash`    |
| `clue_jobs` | `entityId + requestedAt`；`status + requestedAt`   |
| `clues`     | `entityId + createdAt`；`entityId + type`；`jobId` |
| `feedback`  | `clueId`；`entityId + createdAt`                   |

具体索引以 CloudBase 控制台/文档支持的复合索引方式配置。

### 7.4 数据量与安全（个人）

- 单用户、低频：文档库足够。
- 安全规则：默认 **仅云函数管理员权限读写**；前端不直连写敏感集合，或通过云函数代理。
- 不在前端暴露 LLM / 数据源密钥。

### 7.5 不在库内存储的内容

- 实时全市场 Tick
- 未校验的 LLM 原始胡言（只存通过 schema 的线索；可选存 raw 到日志集合便于调试）

## 8. API 草案（云函数 HTTP）

| 方法     | 路径                      | 说明                                             |
| -------- | ------------------------- | ------------------------------------------------ |
| GET      | `/api/entities/search?q=` | 代码/名称搜索                                    |
| GET      | `/api/entities/:id`       | 实体档案 + 关键边摘要                            |
| POST     | `/api/clue-jobs`          | body: `{ code }` 或 `{ entityId }` → `{ jobId }` |
| GET      | `/api/clue-jobs/:jobId`   | 任务状态                                         |
| GET      | `/api/entities/:id/clues` | 线索列表（type、时间筛选）                       |
| GET      | `/api/clues/:id`          | 线索详情                                         |
| POST     | `/api/clues/:id/feedback` | `{ label }`                                      |
| GET/POST | `/api/watchlist`          | V0.2                                             |

所有错误响应不包含密钥与内部 prompt 全文。

## 9. 单标的生成流水线（Worker）

1. **Resolve：** code → `entities`（无则拉取基础档案后 upsert）
2. **Hydrate graph：** 读/补 `edges`（行业同业、ETF 成分若 kind=etf）
3. **Retrieve documents：** 近 N 日公告 + 有限新闻/政策；写入 `documents`
4. **Build context pack：** 实体档案 + 边摘要 + 文档摘录（控制 token）
5. **LLM generate：** 严格 JSON 数组；system 强调非投资建议、禁止无来源关系
6. **Validate & filter：** schema + 禁词 + 无证据丢弃
7. **Persist：** `clues` + `clue_jobs.status=done`
8. **失败：** `status=failed` + `errorMessage`；可重试

**股票 vs ETF：**

|        | 股票           | ETF                                       |
| ------ | -------------- | ----------------------------------------- |
| 骨架   | 行业同业边     | 跟踪指数、etf_holds 成分边                |
| 强线索 | 公告、经营事件 | 结构事实、成分与主题新闻、规模/份额若可得 |
| 跳转   | 同业实体       | 成分股实体                                |

## 10. 前端信息架构（Web）

### 10.1 标的页

- 头部：代码、名称、kind、行业或跟踪指数、中性档案一句
- Tab：全部 / 公告 / 主题政策 / 同业 / ETF结构 / 风险 / 待验证
- 列表卡片：类型、标题、时间、为何相关摘要、置信
- 详情：证据列表、下一步 dig、反馈按钮
- ETF 增区：前十大成分表（事实）→ 跳转

### 10.2 状态

- job `pending|running`：展示生成中
- `failed`：可重试
- 空线索：展示「暂无足够来源」而非假卡片

## 11. 外部数据（原则）

CloudBase **不自带** A 股投研全套数据。实现阶段再锁定具体供应商，原则：

| 数据          | 用途          | 原则                        |
| ------------- | ------------- | --------------------------- |
| 码表/基础档案 | 实体          | 可核对、可更新              |
| 行业分类      | peer 边       | 结构化入库，不靠 LLM 猜同业 |
| ETF 成分/档案 | etf_structure | 带 `asOf`                   |
| 公告          | announcement  | 标题+链接+时间至少具备      |
| 新闻/政策     | theme_policy  | 有限源，重质量              |
| 行情          | 仅上下文展示  | **不**驱动买卖建议          |

采数以 **增量、自选优先** 为主；全市场狂爬不在云函数内做。

## 12. 数据来源边界：API/结构化事实 vs LLM 生成

**总原则：**

- **事实层**（是什么、发生了什么、和谁有关）→ 只来自 API / 披露文件 / 结构化入库，**禁止 LLM invent**。
- **理解层**（怎么归纳、为何相关、下一步查什么）→ 允许 LLM 生成，但必须挂在事实层证据上。
- UI 应能区分：档案/表格/链接 = 事实；线索正文中的叙述 = 模型整理（可标注「AI 整理」）。

### 12.1 总览

| 层级                                   | 来源                     | 可否被 LLM 改写                    |
| -------------------------------------- | ------------------------ | ---------------------------------- |
| 实体档案、代码、市场、行业分类         | 数据 API / 码表          | **否**（只展示原文/字段）          |
| ETF 跟踪指数、成分、权重、规模/份额    | 数据 API / 基金披露      | **否**                             |
| 同业列表（谁和谁同行业）               | 行业分类结构化边         | **否**                             |
| 公告/新闻标题、时间、URL、原文摘录     | 公告/新闻 API 或抓取入库 | **否**（摘录可截断，不改写事实）   |
| 线索的「标题 / 为何相关 / 下一步 dig」 | LLM                      | **是**（基于上文事实包）           |
| 待验证问题 open_question               | LLM                      | **是**                             |
| 风险线 risk_counter 的表述             | LLM                      | **是**（事件本身须来自 documents） |
| 买卖建议、预测涨跌                     | —                        | **禁止任何来源生成**               |

### 12.2 按页面模块拆分

#### A. 标的头部档案（纯 API / 库内结构化）

| 呈现字段                       | 来源                                                                            | LLM？  |
| ------------------------------ | ------------------------------------------------------------------------------- | ------ |
| 代码、名称、市场（SH/SZ/BJ）   | 码表 / 行情基础 API                                                             | 否     |
| kind：股票 / ETF               | 码表                                                                            | 否     |
| 行业代码/名称                  | 行业分类 API → 写入 `entities`                                                  | 否     |
| ETF：跟踪指数名称/代码         | ETF 档案 API                                                                    | 否     |
| 近价、涨跌幅、成交额（若展示） | 行情 API                                                                        | 否     |
| 一句话「中性档案」             | **优先**用模板拼接字段（行业+市值口径等）；若用 LLM 只能改写已有字段，且标注 AI | 默认否 |

#### B. ETF 结构区（纯 API）

| 呈现字段                   | 来源                                     | LLM？ |
| -------------------------- | ---------------------------------------- | ----- |
| 前十大成分代码/名称/权重   | 持仓/披露 API → `edges` type=`etf_holds` | 否    |
| 持仓快照日期 asOf          | 同上                                     | 否    |
| 规模、份额、净申赎（若有） | ETF 行情/披露 API                        | 否    |
| 「从成分跳转」链接         | 前端根据 code 跳转                       | 否    |

**注意：** 「ETF 结构**线索**」卡片（type=`etf_structure`）里的**叙述句**可以是 LLM 写的，但卡片内引用的成分名、权重、日期必须来自上述 API 字段，模型不得编造成分。

#### C. 同业区（列表=API，解读=LLM）

| 呈现字段                              | 来源                                        | LLM？  |
| ------------------------------------- | ------------------------------------------- | ------ |
| 同业标的列表（代码、名称）            | 同行业分类 → `edges` `peer_same_industry`   | 否     |
| 同业近期公告标题列表                  | 对各 peer 调公告 API                        | 否     |
| 线索「同业线」的标题/为何相关/nextDig | LLM 基于「主标的 + peer 列表 + 其公告摘要」 | **是** |

#### D. 公告 / 新闻 / 政策证据（纯 API 入库）

| 呈现字段                     | 来源                                   | LLM？                              |
| ---------------------------- | -------------------------------------- | ---------------------------------- |
| 标题、发布时间、链接、公告号 | 巨潮等公告 API / 新闻 API              | 否                                 |
| 摘录 excerpt                 | API 摘要字段或正文截断入库 `documents` | 否（禁止模型「编造摘录」冒充原文） |
| 列表排序（按时间）           | 后端排序                               | 否                                 |

#### E. 线索卡片（混合：骨架事实 + LLM 文案）

每条 `clues` 记录拆成两段责任：

| 字段                 | 来源                                             | LLM？                                              |
| -------------------- | ------------------------------------------------ | -------------------------------------------------- |
| `type`               | 由流水线指定或模型在枚举内选择                   | 半：须在 6 类枚举内                                |
| `title`              | LLM                                              | 是                                                 |
| `whyRelated`         | LLM                                              | 是                                                 |
| `nextDig`            | LLM                                              | 是                                                 |
| `evidence[]`         | **必须**引用已存在的 `documents` / 结构化字段    | **否**（只允许拷贝 id/标题/url/时间/已存 excerpt） |
| `relatedEntityIds`   | 优先来自 `edges` 或 evidence 中出现的已解析 code | 否（禁止模型虚构未入库实体 id）                    |
| `confidence`         | 规则引擎：有公告链接=high，仅舆情=medium/low     | **规则，非模型随意**                               |
| `freshnessAt`        | 取 evidence 中最新 `publishedAt`                 | 规则                                               |
| `open_question` 正文 | LLM                                              | 是（须能对应本 job 上下文）                        |

**校验：** 若 `evidence` 无法对应到本次 retrieve 的 documentId/url，卡片丢弃。

#### F. 风险与反方线（混合）

| 部分                            | 来源                                          | LLM？          |
| ------------------------------- | --------------------------------------------- | -------------- |
| 风险事件是否存在                | 检索到的公告/新闻（立案、问询、亏损、减持等） | 否（有无事实） |
| 如何表述风险、为何相关、nextDig | LLM                                           | 是             |
| 无风险检索命中时的占位文案      | **固定模板**（非模型编造监管事件）            | 否             |

#### G. 待验证问题（LLM）

| 部分                   | 来源                   | LLM？             |
| ---------------------- | ---------------------- | ----------------- |
| 问题列表文案           | LLM 基于本 job 事实包  | 是                |
| 问题中点名的 code/数据 | 只能来自事实包已有实体 | 校验丢弃虚构 code |

### 12.3 流水线阶段谁产出什么

```text
[1] 数据 API / 披露
      → entities, edges, documents, 行情快照
      → 全部是「既有数据」

[2] 组装 context pack（服务端代码，非 LLM）
      → 把结构化字段 + 文档摘录打成 prompt 输入
      → 不新增事实

[3] LLM
      → 只输出：线索 title / whyRelated / nextDig / open_question 文案
      → 以及指向 evidence 的引用（documentId 或 url，必须落在 pack 内）

[4] 规则校验（服务端代码）
      → 丢弃无证据卡片、禁词、虚构 entity、非法 type
      → 计算 confidence / freshnessAt
      → 写入 clues
```

### 12.4 UI 呈现建议（避免用户误解）

| 区域                         | 标注建议                                     |
| ---------------------------- | -------------------------------------------- |
| 档案、成分表、公告列表、链接 | 不标 AI；显示「数据更新于 …」                |
| 线索标题与「为何相关」       | 可标「AI 整理」                              |
| 证据区                       | 显示原始标题+链接+时间，样式上与 AI 正文区分 |
| 待验证问题                   | 标「AI 生成的研究问题，非结论」              |

| -------------------------------------------------------- | ------------------------------------ |
| 这是什么股票/ETF？成分是谁？同业有谁？有哪些公告？       | **API / 结构化数据**                 |

## 13. LLM 使用原则

- 职责：摘要、聚类、表述、生成 open_question 与 nextDig
- 不职责：预测涨跌、给出操作指令、无证据创造股权/供应链/成分/同业关系
- 不职责：伪造公告标题、摘录、URL、权重、财报数字
- 输出：结构化 JSON only；evidence 仅引用 retrieve 结果
- 版本：`promptVersion` 写入 `clues.modelMeta` 便于对比
