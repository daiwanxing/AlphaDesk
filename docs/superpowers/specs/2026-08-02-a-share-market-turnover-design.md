## 1. 架构总览

### 1.1 原则

- **读路径：** 前端独立页只调自有 HTTP API，**不**浏览器直连东财（CORS / UA / 风控更可控）。
- **写路径：** 本模块**无 LLM、无任务队列**；可选将「昨收全天」写入文档库作按日缓存。
- **休市零轮询：** 前端在非连续竞价时段停止 `setInterval`；**不**部署为本模块服务的 15s CloudBase Timer。
- **YAGNI：** 第一版不做分时同时刻对比、不做近几日柱状、不做全市场逐票加总。

### 1.2 逻辑流

```text
[导航] 事件追踪 | A股量能
    → `/` 现有 Mag7 + FOMC 时间线（及 `/events/$eventId` 详情）
    → `/turnover` 成交额看板

[页面] /turnover
    → 进入时 GET 一次 get-market-turnover
    → 若处于 A 股连续竞价时段：每 15s 再 GET
    → 离开时段 / 离开页面：清除轮询

[HTTP] get-market-turnover
    → 读昨收缓存（pipeline_meta 或专用小文档）；缺失则拉日 K 并写回
    → 拉东财实时成交额（轻量 ulist / 等价一次请求覆盖三市代表标的）
    → 计算差额、百分比、合计
    → 返回 JSON（含 session 状态、口径说明字段）
```

### 1.3 部署边界

| 组件     | 放哪                                                  | 职责                                    |
| -------- | ----------------------------------------------------- | --------------------------------------- |
| 前端路由 | 静态托管 SPA：`/` + `/turnover`（+ 现有详情）         | 两入口；量能页盘中 15s 轮询；休市停轮询 |
| HTTP API | CloudBase `get-market-turnover`                       | 代理东财 + 昨收缓存 + 聚合              |
| 昨收缓存 | 文档库（建议复用 `pipeline_meta` 文档 id 或独立 doc） | 每交易日最多刷新一次昨收全天额          |

网关路径示例：`https://<envId>-<appId>.tcloudbaseapp.com/get-market-turnover`

### 1.4 双路由与导航（锁定）

应用是 **两个一级入口**，不是把量能塞进事件首页。

| 路由        | 名称（导航文案） | 职责                                                         |
| ----------- | ---------------- | ------------------------------------------------------------ |
| `/`         | **事件追踪**     | Mag7 财报 + FOMC 时间线（现状）；详情仍为 `/events/$eventId` |
| `/turnover` | **A股量能**      | 沪 / 深 / 京成交额看板（本规格）                             |

- 根布局（`__root.tsx`）增加主导航：`事件追踪` | `A股量能`（`Link` + active 态）
- 品牌区可保留「Investor」；副文案可改为覆盖两模块，或仅保留品牌、模块名放在 nav
- **默认落地页**：第一版仍为 `/`（事件）；不强制改默认首页
- 离开 `/turnover` 时必须清掉轮询 timer（与 §2.2 一致）

## 2. 产品形态（UI）

### 2.1 布局（`/turnover`）

- **组件：** 优先 HeroUI（如 `Card` / `Chip` 或 Badge / `Button` / `Spinner` / `Alert` 等）；与根布局已有 HeroUI 用法一致，避免再引入另一套 UI 库
- 页标题：如「A股量能」
- 三列卡片：沪市 / 深市 / 京市
  - 今日成交额（格式化：亿 / 万亿）
  - 较上日：差额 + 百分比，增量/缩量用颜色区分
- 合计行：三市之和 + 较上日合计变化
- 固定提示文案：`盘中对比昨收全天 · 非同时刻`
- 元信息：数据更新时间、当前会话状态（盘中 / 午休 / 已收盘 / 休市）——会话态用 HeroUI Chip/Badge 呈现（见 §2.4）

### 2.2 交互

| 状态                          | 行为                                         |
| ----------------------------- | -------------------------------------------- |
| 进入页面                      | 立即请求一次                                 |
| 连续竞价中                    | 15s 自动刷新                                 |
| 午休 / 收盘后 / 周末 / 节假日 | **不**自动刷新；可保留手动刷新               |
| 请求失败                      | 保留上一帧；展示错误；退避后再试（避免狂打） |

### 2.3 交易时段（第一版）

- 时区：**Asia/Shanghai**
- 连续竞价近似：工作日 `09:30–11:30`、`13:00–15:00`
- 节假日：第一版可用「仅工作日」近似；可选后续接交易日历。误在假日轮询时仍应低频且可接受（2 用户），但目标是接日历后停掉。

**明确不包含：** 为量能模块配置 CloudBase Timer 定时写库。

### 2.4 会话态 UI（含周末）

页面顶部用 **状态条 / 徽章** 明确当前会话，避免用户误以为仍在盘中刷新。

| `session`    | 何时                   | UI 表现                                                                                    | 数字含义                                                                                 |
| ------------ | ---------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `continuous` | 工作日连续竞价         | 徽章「盘中」；显示自动刷新；三卡 + 较上日（进度对比）                                      | 今日累计 vs 昨收全天                                                                     |
| `lunch`      | 工作日 11:30–13:00     | 徽章「午休 · 暂停刷新」；保留上午最后一帧；可选手动刷新                                    | 同上（冻结）                                                                             |
| `closed`     | 工作日收盘后           | 徽章「已收盘」；**不**轮询；三卡展示**本日全天**终值 vs 上一交易日全天                     | 日终对比（方案 A 在收盘后才严格）                                                        |
| `weekend`    | 周六、周日             | 徽章「周末休市」；副文案如「下一交易日开盘后更新」；**不**轮询；可选弱化「较上日」进度语义 | 展示**上一交易日**三市全天成交额（及再上一交易日作对比，若有）；**不要**假装「今日累计」 |
| `holiday`    | 法定节假日（有日历后） | 同周末文案改为「节假日休市」                                                               | 同周末                                                                                   |

**周末/节假日硬性要求：**

1. 视觉上必须一眼看出「今天没开市」（徽章 + 文案），不能只显示三张数字卡、看起来像盘中。
2. **禁止**自动 15s 轮询。
3. 数字用**最近一个交易日收盘快照**（来自日 K / 缓存），标签写成「上交易日成交额」或「截至 YYYY-MM-DD」，避免「今日」。
4. 「较上日」在休市日改为「较再上一交易日」或隐藏 delta、只展示上一日绝对值——第一版推荐：**展示上一日三市全天 + 较再上一日的增减**（仍是方案 A 的历史对比），并注明对比基准日期。
5. 手动刷新：允许，但成功后仍不启动轮询，直到进入下一 `continuous`。

线框语义（周末）：

```text
[周末休市]  下一交易日开盘后恢复实时更新
沪 / 深 / 京  — 上交易日（2026-08-01）全天
合计 …  ·  较再上一日 ↑/↓ …
```

## 3. 数据口径

### 3.1 实时（今日累计）

轻量代表标的（与常见软件展示接近，实现时在代码/UI 标注来源）：

| 展示名 | 建议标的                                 | 说明                                                   |
| ------ | ---------------------------------------- | ------------------------------------------------------ |
| 沪市   | 上证指数 `1.000001` 成交额               | 与「沪市」高度接近                                     |
| 深市   | 深证成指或深证综指（实现选定一种并固定） | **非**全深市逐票加总；UI 可写「深市（成指/综指口径）」 |
| 京市   | 北证50 `0.899050` 或京市代表             | 轻量近似；不做全 BJ 分页加总                           |

合计 = 三市数值之和（同一口径下相加）。

### 3.2 较上日（方案 A）

- **基准：** 同一标的上一交易日 **日 K 成交额**（全天）
- **对比：** `今日实时累计 − 昨收全天`、`(今日 − 昨收) / 昨收`
- **盘中解读：** 早盘常显示相对「昨收全天」缩量，属预期行为；文案必须说明

### 3.3 昨收缓存

- Key：交易日日期 + 标的
- 每个交易日每个标的最多从东财拉一次日 K；命中缓存则跳过
- 缓存失效：新交易日开盘后发现「昨日」已变

## 4. HTTP API 草图

### 4.1 `GET /get-market-turnover`

响应示例（字段名实现时可微调）：

```json
{
  "ok": true,
  "asOf": "2026-08-02T10:42:00+08:00",
  "session": "continuous",
  "compareMode": "vs_prev_full_day",
  "disclaimer": "盘中对比昨收全天 · 非同时刻",
  "markets": [
    {
      "id": "sh",
      "label": "沪市",
      "source": "上证指数",
      "amount": 1190000000000,
      "prevFullDayAmount": 1106000000000,
      "delta": 84000000000,
      "deltaPct": 0.076
    }
  ],
  "total": {
    "amount": 2890000000000,
    "prevFullDayAmount": 2820000000000,
    "delta": 70000000000,
    "deltaPct": 0.024
  }
}
```

`session` 枚举（与 §2.4 对齐）：`pre_open` | `continuous` | `lunch` | `closed` | `weekend` | `holiday`。  
第一版至少实现：`continuous` | `lunch` | `closed` | `weekend`（`holiday` 可先并入 weekend 文案或同逻辑）。

### 4.2 错误

- 上游失败：`ok: false` + `error`；HTTP 可仍 200 或 502（与现有 `get-briefs` 风格对齐）
- 云函数侧：超时与重试有限；**禁止**在单次请求内对东财打分页轰炸

### 4.3 限流与风控（上游）

- 东财为免费公开接口，无正式 SLA；按 IP 可能限流/断连
- 2 用户 × 15s × 约 1 次上游请求/刷新：风险低
- 硬约束：实时路径保持 **O(1) 请求**；昨收走缓存
- 后续若需再压：在云函数对「今日快照」加 10–15s 短 TTL（方案 2）
